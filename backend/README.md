# Сервис заявок «Перфекто»

Форма отправляет `POST /lead`. Node.js проверяет номер и согласие, сохраняет
заявку в SQLite и только потом подтверждает приём. Уведомление идёт отдельно
через очередь MAX. При сбое заявка остаётся в базе, а интервал повтора растёт.
В сообщении MAX есть номер заявки, по которому можно сверить доставку.

## Локальная проверка

- Нужен Node.js 24. Устанавливать npm-пакеты для бэкенда не нужно.
- Скопировать `.env.example` в `.env`, если файла ещё нет. Токен берётся из [MAX для бизнеса](https://dev.max.ru/docs-api/).
- Получатель открывает бота и нажимает «Начать». Команда `npm run capture-id` из
  папки `backend` проверяет токен и выводит ID для `MANAGER_USER_ID`. Если бот уже
  работает через webhook, получать ID нужно через его входящие события.
- При ошибке сертификата взять корневой и выпускающий сертификаты Минцифры с
  [Госуслуг](https://www.gosuslugi.ru/crt), объединить их в PEM и перед запуском
  указать путь в переменной окружения `NODE_EXTRA_CA_CERTS`.
- Запустить `npm start` из `backend`. Проверка `http://127.0.0.1:8787/health` возвращает `ok`.
  Из корня запустить `python -m http.server 8080 --bind 127.0.0.1` и открыть
  `http://127.0.0.1:8080/#contacts`. Для теста с реальным ботом использовать отдельный
  `DB_FILE` и явно помечать имя словом «ТЕСТ».

GitHub Pages показывает ссылку на звонок. На рабочем домене Nginx проксирует `/lead`
в Node.js. `ALLOWED_ORIGIN` должен совпадать с адресом сайта. Версия текста согласия
задаётся в форме и бэкенде. При смене редакции нужно обновить обе стороны.

## Уведомления

- Настроить личного бота Telegram через BotFather и открыть его в своём чате кнопкой «Старт».
  Указать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в локальном `.env` сервиса.
  При сбое SQLite, очереди, MAX, резервной почты или процесса Telegram получает
  только тип и код ошибки. Одинаковые ошибки ограничены частотой в рамках одного процесса.
  Если выключен весь сервер или у него пропала сеть, нужен внешний мониторинг.
- Резервная почта включается только с `SMTP_PASS`. При ошибке MAX может уйти
  письмо с номером заявки. SMTP должен быть согласован с владельцем данных.
- Обычные повторы и повторная отправка формы с тем же ключом защищены от дублей.
  Если MAX принял сообщение, а процесс упал до отметки доставки, возможен повтор
  с тем же номером заявки. Рабочая база и доступ к выгрузкам должны быть закрыты.

`npm run leads > leads.csv` — локальная выгрузка на сервере. Доступа к базе через
HTTP нет. Инструкция по запуску и резервному копированию — в [deploy/README.md](../deploy/README.md).
