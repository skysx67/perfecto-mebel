# Бэкенд приёма заявок → SQLite + MAX

Маленький сервис без внешних зависимостей. Принимает заявку с лендинга,
сохраняет её в базу **SQLite** и присылает уведомление менеджеру в мессенджер **MAX**.

```
Форма на сайте  →  POST /lead  →  server.js  ─┬─→ запись в SQLite (leads.db)
                                              └─→ бот MAX пишет менеджеру
```

## Файлы

| Файл | Назначение |
|------|-----------|
| `server.js`       | HTTP-сервер: приём заявок, запись в базу, отправка в MAX |
| `db.js`           | Хранилище SQLite (встроенный `node:sqlite`, без зависимостей) |
| `max.js`          | Клиент Bot API MAX (вся специфика API — только здесь) |
| `capture-id.js`   | Разово узнать `user_id` менеджера |
| `export-leads.js` | Выгрузка всех заявок в CSV для Excel |
| `.env`            | Секреты и настройки (НЕ коммитить) |

## Требования

- **Node 24** (проверено). Нужен встроенный модуль `node:sqlite` — в более старых
  версиях он работает только с флагом `--experimental-sqlite`, поэтому берём 24.
- Внешних npm-пакетов нет — `npm install` не требуется.

**Разворачивание на сервере — см. [`../deploy/README.md`](../deploy/README.md)** (один скрипт ставит всё).

## Быстрый старт (локально)

```bash
cp .env.example .env      # заполнить MAX_TOKEN (и позже MANAGER_USER_ID)
npm run capture-id        # узнать свой user_id (см. ниже)
npm start                 # запустить сервер
```

Проверка: `curl http://localhost:8787/health` → `ok`.

## Ручные шаги в MAX (один раз)

1. **Создать бота.** В MAX найти **@MasterBot**, нажать «Начать», отправить `/create`,
   придумать ник (заканчивается на `bot`) и имя. MasterBot пришлёт **токен** — вставить
   в `.env` как `MAX_TOKEN`.
2. **Менеджер жмёт «Начать».** Тот, кому падают заявки, открывает бота и нажимает
   «Начать» (бот не может написать первым — ограничение MAX, как в Telegram).
3. **Узнать user_id менеджера:**
   ```bash
   npm run capture-id
   ```
   Скопировать показанный `user_id` в `.env` → `MANAGER_USER_ID`, перезапустить сервер.

## Сертификаты Минцифры (важно на сервере!)

`platform-api2.max.ru` отдаёт российский сертификат, которому Node по умолчанию не
доверяет — без этого шага запросы к API падают с `unable to get local issuer certificate`.
На сервере:

1. Скачать корневой и промежуточный сертификаты с https://www.gosuslugi.ru/crt
   (или https://gu-st.ru/content/lending/) и склеить в один файл `russian-ca.pem`.
2. Прописать путь в `.env`: `NODE_EXTRA_CA_CERTS=/opt/perfecto/russian-ca.pem`.

## Локальная проверка полного цикла (на своём ПК)

Проверить связку «сайт → бот в MAX» целиком, не покупая сервер:

1. В `.env` временно раскомментируй `NODE_TLS_REJECT_UNAUTHORIZED=0`
   (обход сертификата Минцифры — ТОЛЬКО для локального теста, на сервере так НЕ делать).
2. Запусти бэкенд: `npm start` (слушает `:8787`).
3. В другом окне подними сайт из корня проекта: `npx serve -l 8080`
   (или любой статический сервер) и открой http://localhost:8080
4. Заполни форму и отправь. При открытии с `localhost` сайт сам шлёт заявку на
   локальный бэкенд (см. `LEAD_ENDPOINT` в `index.html`) → тебе придёт сообщение в MAX,
   а заявка ляжет в `leads.db`.
5. После проверки закомментируй `NODE_TLS_REJECT_UNAUTHORIZED=0` обратно.

Содержимое базы: `npm run leads` (выгрузка в CSV).

## Резервная доставка на почту

Если бот MAX недоступен (упал сервер, проблемы с сертификатом, сбой у MAX),
заявка **не теряется**:

1. Заявка сохраняется в базу.
2. Уведомление в MAX не прошло → заявка **дублируется письмом** на `MAIL_TO`.
3. Сервис сам повторяет отправку **каждые 2 минуты** (настройка `RETRY_MS`).
4. Как только бот заработал — все накопленные заявки уходят в MAX
   с пометкой «доставлена с задержкой». Повторных писем не шлём.

Заявки старше суток из очереди выбывают (они уже пришли письмом).

**Включение** — в `.env` заполнить `SMTP_PASS`:

```
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=perfecto72@mail.ru
SMTP_PASS=            ← пароль для внешних приложений
MAIL_TO=perfecto72@mail.ru
```

Пароль для mail.ru: **Почта → Настройки → «Пароли для внешних приложений» → создать**.
Это отдельный пароль (не от ящика), его можно отозвать в любой момент.
Если `SMTP_PASS` пустой — резерв выключен, заявки всё равно копятся в базе
и уходят в MAX при первой возможности.

Проверить, что почта настроена: в логе при старте будет
`резервная почта: вкл (perfecto72@mail.ru)`.

## База данных

- Файл `leads.db` (SQLite) создаётся автоматически при первом запуске, лежит рядом с кодом
  (путь можно переопределить переменной `DB_FILE`). В `.gitignore` — в репозиторий не попадёт.
- Таблица `leads`: `id, ts, name, phone, email, source, furniture, measure, design, terms,
  raw (полный JSON), ip, ua, notified`.
- **Выгрузка в Excel:** `npm run leads > leads.csv` (UTF-8, разделитель `;`).
- **Просмотр в браузере:** задать `ADMIN_KEY` в `.env`, открыть
  `http://адрес:8787/leads?key=ВАШ_КЛЮЧ`.
- **Перенос:** просто скопировать файл `leads.db` на новый сервер.

## Постоянная работа (сервер)

Под pm2 или systemd, например:
```bash
npm i -g pm2
pm2 start server.js --name perfecto-lead --node-args="--env-file=.env"
pm2 save && pm2 startup
```

## Подключение сайта

После деплоя вписать URL сервиса в `index.html`, переменная `LEAD_ENDPOINT`
в начале `<script>` (например `https://ваш-сервер.ru/lead`). Пока переменная пустая —
сайт работает как раньше (показывает «заявка принята» + гид), просто не шлёт заявку в MAX.

## Передача бота другому владельцу

Код и база не привязаны к конкретному боту/менеджеру — вся привязка в `.env`.
Чтобы передать (у MAX бот нельзя просто «переписать» на другого — нужен новый):

1. Новый владелец создаёт **своего** бота через @MasterBot → получает **новый токен**.
2. Новый менеджер открывает этого бота и жмёт «Начать».
3. В `.env` меняются два значения: `MAX_TOKEN` (новый токен) и `MANAGER_USER_ID`
   (`npm run capture-id`). При желании — `ADMIN_KEY`, `ALLOWED_ORIGIN`.
4. Перезапустить сервис. Код, база и формат сообщений — те же.

## Где разместить

Нужен хост, с которого доступен `platform-api2.max.ru` и где можно поставить
сертификаты Минцифры — надёжнее всего **недорогой российский VPS** (Timeweb,
Selectel, Reg.ru; ~150–300 ₽/мес). Западные serverless (Cloudflare Workers, Vercel)
не подойдут: их нельзя научить доверять российским сертификатам.

## Примечание

Bot API MAX активно меняется (июль 2026: миграция домена на `platform-api2.max.ru`,
переход на российские сертификаты). Если что-то отвалится — сверяться с
